# API contract (glasses -> server)

Base: `VITE_API_BASE` (default http://localhost:8787). JSON unless noted. `deviceId` is a random UUID minted once on the glasses. It is an identifier, not a credential: the first `/api/device/pair` for a new device returns a random `deviceSecret` (once), which the glasses keep in bridge localStorage and send as the `x-device-secret` header on every call (pair included, once they have it). Calls with a missing or wrong secret get 403, which the glasses treat as "not paired".
Server `state` values: IDLE, WAITING, CONFIRMING, PAID, SHORT, EXTRA, DUPLICATE, FAKE, UNMATCHED, LATE, VOID. Money is a decimal string ("12.00").

| Call | Request | Response |
| --- | --- | --- |
| POST /api/device/pair | `{deviceId}` (+ `x-device-secret` once known) | `{paired:boolean, code?:string, shopName?:string, deviceSecret?:string}` (code like TILL-482193, 6 digits, valid 30 min, refreshed on the next call; `deviceSecret` only on the call that mints/re-issues it; a paired device with a wrong/missing secret gets 403; 429 when over the rate limit) |
| POST /api/till/arm | `{deviceId, amount:"12.00", asset:"USDT"\|"GRAM"}` | `{saleId}` |
| GET /api/till/status?deviceId= | | `{state, sale?:{saleId, amount, asset, receivedTotal, from?, ageSec? (seconds since the payment; since creation before payment), paidAt? (epoch s of the payment), extra?, missing?}, unmatched?:{amount, from, paymentId, asset?, ageSec? (seconds since the payment), utime? (epoch s)}, timing?:{chainSec (payment utime), seenAfterSec? (first sight, pending or final), paidAfterSec? (PAID detected)}, chainDelayed?:boolean (true when the server has not read the chain for 15 s), chainAgeSec?:number (seconds since the last successful chain read); both are present only when delayed}` |
| POST /api/till/void | `{deviceId, saleId}` | any 200 |
| POST /api/till/receipt | `{deviceId, saleId}` | any 200 |
| POST /api/till/attach | `{deviceId, saleId, paymentId}` | any 200. Refused with 404 (no such unmatched payment, or it is already attached elsewhere) and 409 (sale void/expired/not open, payment older than the sale, payment not finalized yet) |
| GET /api/today?deviceId= | | `{count, total, asset}` (DUPLICATE money is counted) |
| GET /api/network | | `{network:"testnet"\|"mainnet"}`. The setup and pay pages call it and block a wallet on the other network. |
| GET /api/pay/info (Mini App, not the glasses) | | includes `due` (decimal string) and `dueRaw` (smallest units, string): the amount still missing for a SHORT sale (the pay page asks only for that amount), or the full amount otherwise. The Mini App shows "Pay <shop>" with the amount and asset. |
| POST /api/stt?deviceId= | raw body, `content-type: audio/wav` (PCM s16le 16 kHz mono, 6 s max) | `{text, amount: "12.00"\|null, asset: "USDT"\|"GRAM"}` (asset follows the spoken currency, e.g. "five gram" gives GRAM; 12 requests per minute per device, 30 per IP, 20 s upstream timeout, 504 on timeout) |

`CONFIRMING` = a matching payment (right ref, allowlisted token) is on chain but not finalized yet: shown as "PAYMENT SEEN, confirming", never as PAID. PAID is only ever returned after finality (unchanged rule). The server watcher ticks every 1 s while a sale is open when a TON Center API key is set (2 s otherwise).

Glasses behavior: polls status every 2 s while WAITING/SHORT/CONFIRMING and also on FAKE and UNMATCHED, so an honest payment after a fake still flips the same sale to PAID with no taps. Sale states WAITING, CONFIRMING, PAID, EXTRA, SHORT, DUPLICATE, FAKE, UNMATCHED, LATE render as big-type bitmaps (two 200x96 4-bit greyscale indexed PNG image containers: status word + glyph, amount) over two text lines (detail, hint); IDLE, pairing, listening and presets stay text. If rebuilding the page or an image update fails the glasses fall back to the plain text layout (after 2 consecutive failures they stay on text). UNMATCHED shows amount, sender and age; if the unmatched amount differs from the sale amount, the first tap shows "AMOUNT DIFFERS" and only a second tap attaches. FAKE shows "NOT PAID, still waiting" and a double tap cancels the sale (a single tap no longer dismisses it). When `chainDelayed` is true the glasses show "Chain check delayed - do not hand over yet". Any non-2xx or network error shows "Offline - retrying". PAID is shown only when the server returns state PAID/EXTRA. CORS must allow the simulator/WebView origin. `status` should return IDLE (or VOID) when no sale is open.
